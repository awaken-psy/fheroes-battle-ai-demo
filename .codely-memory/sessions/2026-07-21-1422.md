## 会话摘要

对 fheroes-battle-ai-demo 项目进行了全面的代码审查和 R 系列管线重构。修复了 4 个严重 bug（replay buffer 无效、DeepAI 无法加载 MoE checkpoint、Windows 路径不兼容、bottleneck 重复计算 3 次），重构了动作空间（13,566→3,821 维，降低 72%），添加了 selected unit 观测通道和英雄双阶段行动（cast→act）。然后实现了 training-v2 混合对手策略（ClassicAI + 自博弈 + 对手池），跑了 200K 步训练验证。

## 关键决策

### 决策 1：R 系列重构优先于 T 系列优化
- T 系列花了 7 个子里程碑用 MoE 补管线缺陷，但底层管线有 4 个根本问题
- 修复管线后简单架构（纯 CNN）可能不需要 MoE

### 决策 2：动作空间从 pos×target 改为 enemy_index×position
- Attack 子空间从 9,801 维降到 56 维
- policy head 参数从 5.23M 降到 1.47M
- 合法动作比例从 0.2% 提升到 1.5%

### 决策 3：英雄双阶段行动（cast→act）
- 原来 DeepAI 每回合只能二选一（施法或攻击），ClassicAI 可以先施法再攻击
- 现在环境拆为 cast phase + unit phase，DeepAI 和 ClassicAI 对等

### 决策 4：混合对手策略
- 33% vs ClassicAI + 33% 自博弈 + 33% 对手池
- 纯自博弈容易收敛到互怼策略，ClassicAI 从未在训练中被利用

### 决策 5：纯 sparse reward 实验（失败）
- 尝试纯 sparse（无 dense reward），200K 步训练结果 avg ~14%（T6 baseline 57%）
- 分析发现：纯 sparse 在长回合配置（example 120 步）上 credit assignment 太难
- mage_duel 达到 100%（短回合 + 双阶段施法提供密集信号）
- vs ClassicAI 全程负 reward（31 局 mean -0.074），agent 从未学会打败 ClassicAI
- value_loss 不收敛（0.046→0.047），value function 无效

### 决策 6：下一步回退到 dense+sparse 课程
- 恢复 `--phase1-steps 10000 --phase2-steps 30000`
- ClassicAI 比例从 33% 降到 15%（agent 太弱时全负信号有害）
- replay buffer 10→20，update_epochs 回到 4

## 踩坑/经验

1. **replay buffer bug 隐藏了 7 个里程碑**：T9b 引入 replay buffer 防遗忘，但 minibatch 循环只迭代 fresh 数据（T=len(buffer)），replay 数据拼接了但从未被采样。所有 T9 系列的"遗忘缓解"结论都不可靠。

2. **纯 sparse 在当前设置下不可行**：200K 步 + 4 配置 + 纯 sparse = avg 14%。value function 无法学习（value_loss 不收敛），长回合配置 credit assignment 太难。需要 dense reward 作为 bootstrap。

3. **vs ClassicAI 比例不能太高**：agent 太弱时 vs ClassicAI 全负 reward，这些数据可能有害而非有益。应该先用 dense reward + 自博弈建立基础能力，再逐步增加 ClassicAI 比例。

4. **动作空间缩小 72% 后训练速度提升 40%**：MoE 版 5K 步 32.3s → 纯 CNN 5K 步 19.6s。policy head 不再吞噬模型容量。

5. **双阶段施法对 mage_duel 极其有效**：纯 sparse 下 mage_duel 达到 100%（之前从未超过 77.5%），说明 cast+act 组合是关键战术能力。

6. **PyTorch CUDA 安装陷阱**：`uv pip install` 装的 CUDA 版会被 `uv run` 根据 pyproject.toml 的 `torch>=2.12.0` 约束回退到 CPU 版。需要在 pyproject.toml 中配置 `[[tool.uv.index]]` + `[tool.uv.sources]`。
